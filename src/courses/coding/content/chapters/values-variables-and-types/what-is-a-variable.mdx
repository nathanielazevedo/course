A value on its own is inert — a `42` floating in memory with nothing referring to it is useless. A **variable** is a name bound to a value, giving your code a way to refer to that value again later, pass it around, and change what it refers to over time. This section is about what that binding actually is, and why "variable" means slightly different things in different languages.

### Names and bindings

`let total = 0` creates a **binding**: from this point in the code, the name `total` refers to the value `0`. This is fundamentally a lookup mechanism — when later code reads `total`, the language resolves that name to whatever value it's currently bound to. The name itself has no meaning to the machine; it exists purely for the human reading and writing the code, and could just as well be `x` or `t` as far as execution is concerned (though never should be, for the sake of the next person reading it).

### Variables vs. values

It's worth being precise about a distinction that's easy to blur: the variable is the *name*, the value is the *data*. `total = 5` then `total = 10` doesn't change the value `5` — `5` is immutable and always will be `5` — it changes what `total` refers to, pointing it at a different value entirely. This distinction matters enormously once objects and collections enter the picture (next section covers this directly), because it separates "reassigning what a name points to" from "mutating the data a name currently points to," which are very different operations with very different consequences.

### References

In most modern languages, a variable holding an object or collection doesn't hold the data itself — it holds a **reference** (conceptually, an address) pointing at where the data actually lives. `let a = [1, 2, 3]; let b = a;` makes `b` a second name pointing at the *same* list, not a copy of it — modifying the list through `b` is visible through `a` too, because there's only ever been one list. This is one of the most common sources of confusion for people newer to programming, and Chapter 4's section on passing data covers exactly how it plays out when references cross into function calls.

### Reassignment

**Reassignment** is pointing a variable at a different value: `total = 10` after `total = 5` doesn't touch the `5` anywhere — it just moves the `total` binding onto a new value. Some languages (Rust, and JavaScript's `const`) forbid this by default, requiring you to explicitly opt in to a name being reassignable, precisely because unrestricted reassignment is a common source of bugs where code assumes a name still refers to what it referred to earlier.

### Mutation

**Mutation** is different: it's changing the data a value itself contains, in place, without changing which value a variable refers to. `list.append(4)` doesn't reassign `list` to a new list — it changes the existing list's contents, and every other variable referencing that same list sees the change immediately. Reassignment and mutation are independent axes — a variable can be non-reassignable but still refer to mutable data (a `const` array in JavaScript can still have elements pushed onto it), which trips people up until the distinction is made explicit like this.

### Constants

A **constant** is a binding that's disallowed from being reassigned after its initial value is set — `const` in JavaScript, `final` in Java, `let` (by default) in Rust. It's a tool for communicating and enforcing intent: "this name will always refer to this same value for the rest of its scope," which makes code easier to reason about and lets a compiler catch accidental reassignment as an error rather than a silent bug.
