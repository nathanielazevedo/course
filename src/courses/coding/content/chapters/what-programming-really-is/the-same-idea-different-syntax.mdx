Once you've written a variable, a conditional, a loop, and a function in one language, you already know 80% of what you need to read the same constructs in a language you've never touched. The syntax changes; the idea underneath almost never does. This section is a deliberate side-by-side tour, because seeing the same concept wearing five different outfits is what makes the pattern click.

### Variables across languages

```python
# Python
total = 0
```
```javascript
// JavaScript
let total = 0;
```
```rust
// Rust
let mut total = 0;
```
```go
// Go
var total = 0
```

Four different punctuation styles, one identical idea: bind the name `total` to the value `0` so it can be referred to and changed later. Rust's `mut` and the type-declaration keywords (`var`, `let`) are the languages being explicit about things Python leaves implicit — whether the binding can be reassigned, and how strictly its type is tracked. Chapters 5 and 7 dig into exactly what those differences mean.

### Conditionals across languages

```python
if total > 100:
    apply_discount()
else:
    charge_full_price()
```
```javascript
if (total > 100) {
  applyDiscount();
} else {
  chargeFullPrice();
}
```
```rust
if total > 100 {
    apply_discount();
} else {
    charge_full_price();
}
```

Every one of these is the same three-part shape: a condition, a branch to take if it's true, a branch to take if it's not. Python signals structure with indentation; the others use braces. That's it — that's the entire difference in the concept, even though it's the first thing that makes new syntax feel unfamiliar.

### Loops across languages

```python
for item in items:
    process(item)
```
```javascript
for (const item of items) {
  process(item);
}
```
```go
for _, item := range items {
    process(item)
}
```

All three are the same "iteration" idea covered fully in Chapter 3: walk a collection, doing something with each element, without the programmer manually tracking an index. Older-style `for (int i = 0; i < n; i++)` loops in C-family languages express the identical intent with the counter made explicit instead of hidden.

### Functions across languages

```python
def add(a, b):
    return a + b
```
```javascript
function add(a, b) {
  return a + b;
}
```
```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

Name, parameters, a body, a return value — the shape never changes. Rust additionally requires you to say what type each parameter and return value is; that's a difference in the *type system* (Chapter 2), not in what a function fundamentally is.

### Recognizing concepts beneath syntax

The skill this section is training is a specific kind of pattern recognition: when you see unfamiliar syntax, ask "what concept is this?" before asking "what does this exact character mean?" A curly brace, a colon, an indentation level, a keyword like `fn` or `def` or `function` — these are all just different ways of marking the same handful of structural boundaries. Chapter 15 turns this recognition into an explicit, repeatable method for picking up any new language quickly.
