A pipette tip was introduced back in the liquid-handling chapter as the disposable part that touches liquid. What wasn't covered there is the *logistics* of tips — how a system that fires thousands of them a day keeps itself supplied, tracks what's been used, and avoids ever picking up the wrong one.

### Tip boxes: the unit of supply

Tips arrive and are stored in **tip boxes** — a rigid rack, usually matching an 8-, 12-, or 96-count grid, holding fresh tips upright and ready to be picked up. A tip box is itself built to the SBS footprint, so it sits in a deck position exactly like a plate does, and a robotic arm or liquid handler's own head can move to a specific well position in the box and pick up the tip sitting there — no different, mechanically, from picking up liquid from a plate well.

### Tracking what's used

An automated system needs to know, at every moment, which positions in a tip box still hold a tip and which are empty. This sounds trivial but matters enormously at scale: attempting to "pick up" from an already-empty position wastes a cycle at best, and at worst causes a downstream step to run with no tip attached at all — dispensing air into a well that was supposed to receive reagent. Systems track tip state with a simple internal model (a grid of used/unused flags, updated after every pickup) that must stay in sync with the box's actual physical state — if a tip is manually removed or a box is swapped without updating the system, the model becomes wrong silently.

### Never guessing which tip is which

Beyond tracking availability, a system must never confuse tip *types* — a run needing 20 µL tips for one step and 200 µL tips for another must reliably load from the correct box at each step. This is usually handled by defining tip boxes as typed resources in the method itself (this deck position holds this tip type), rather than relying on a person to have loaded the boxes correctly by eye — the same reasoning that drives labware barcoding, covered next.

### Running out mid-protocol

A protocol that consumes more tips than a single box holds needs a plan for **replenishment** — either loading multiple boxes of the same type up front, or pausing to have a person (or a robotic arm serving a tip-box stack) swap in a fresh box mid-run. A system that simply runs out of tips with no plan for what happens next stalls the entire method, often at the worst possible moment — mid-transfer, with liquid already aspirated and nowhere to dispense it.

Tips are consumed anonymously — one is as good as another of the same type. The next section covers labware that isn't anonymous at all: plates and tubes that must be individually identified and tracked throughout a run.
