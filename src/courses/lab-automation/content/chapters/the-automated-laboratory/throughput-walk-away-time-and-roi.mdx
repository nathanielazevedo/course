The previous section framed automation as a judgment call. This one puts numbers on it. Three measurements — throughput, walk-away time, and return on investment — turn "is this worth automating" from a feeling into a calculation.

### Throughput

**Throughput** is how many samples or plates a system processes per unit time. It's the most visible number, and the one vendors advertise, but it's easy to measure wrong. The throughput that matters is *sustained* throughput — what the system does over an 8-hour shift or a week — not the peak speed of its fastest single step. A liquid handler that pipettes a plate in two minutes is not doing much for total throughput if the plate then waits twenty minutes for a reader that's busy with something else. Throughput is a property of the whole workflow, not any one instrument in it.

### Walk-away time

**Walk-away time** is how long a system runs unattended before it needs a person again — to reload tips, refill reagents, or intervene on an error. A system that runs for ten minutes and then needs someone standing by isn't meaningfully more automated than manual work; a system that runs for eighteen hours overnight has actually freed a person's time, not just their hands.

Walk-away time is often the more important number of the two. A system can have modest throughput and still be extremely valuable if it runs unattended overnight, because the *person's* time — not the machine's — was the actual bottleneck.

### Return on investment

**ROI** ties throughput and walk-away time to money. In its simplest form: what did automation cost to build and maintain, versus what did it save in labor, error, and time? A rough version of the calculation is:

```
ROI = (manual cost per run − automated cost per run) × runs per year
      ─────────────────────────────────────────────────────────────
                          automation cost
```

The automated cost per run isn't zero — reagents, tips, and maintenance still cost money — but the *labor* portion drops sharply, especially once walk-away time is high enough that one person can oversee several runs at once rather than being tied to any single one.

### Why all three numbers, not just one

A high-throughput system with no walk-away time still consumes a person's whole day, just faster. A system with long walk-away time but low throughput may still be worth it if labor was the actual constraint. And a system with great throughput and walk-away time can still have poor ROI if it was wildly expensive to build for a workflow that only runs occasionally — which loops straight back to the frequency and volume questions from the previous section. None of the three numbers alone tells the whole story; together, they're the case for or against automating a given workflow.
