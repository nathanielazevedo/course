Automation is a solution, not a default. It costs money, time, and expertise to build and maintain, so the real question for any workflow isn't "can this be automated" — almost anything can — it's whether automating it is actually worth doing.

### The questions that matter

- **How often does this run?** A protocol run once a year rarely justifies automation, however tedious it is. One run every week, for years, is a different calculation entirely.
- **How many samples per run?** Automating a 12-tube protocol saves little. Automating a 384-well plate replicated across dozens of plates saves a great deal — the same fixed automation effort pays off across far more repetitions.
- **How repetitive is the protocol?** A workflow with a fixed, unchanging sequence of steps automates cleanly. A workflow that a scientist adapts on the fly, sample by sample, resists automation because there's no fixed sequence to encode.
- **How much does variability cost?** If human variability meaningfully affects the result — a sensitive assay, a regulated process — the reproducibility payoff from automation matters even at moderate volume.
- **What does a failure cost?** High-value or irreplaceable samples raise the stakes of getting each step exactly right, which favors automation's consistency even when volume alone wouldn't justify it.

### The fixed cost is the whole argument

Building an automated method has an upfront cost — writing the script, validating it, buying or programming the hardware — that's paid once regardless of how many times the method runs afterward. That fixed cost is spread across every future run. Run the method twice and each run absorbs half the cost; run it two thousand times and the cost per run is negligible. This is why frequency and volume dominate the decision: they're what determines how many times the fixed cost gets divided.

A workflow can also be *partially* automated. Automating only the tedious, repetitive middle of a protocol — leaving judgment-heavy setup or interpretation steps to a person — is often the pragmatic answer, rather than treating automation as all-or-nothing.

### Signs a workflow is a poor automation candidate

Not every repetitive task should be automated. A protocol that changes every few months as the science evolves will cost more to keep re-validating than it saves. A protocol requiring a scientist's judgment at nearly every step — deciding what to do next based on what they see — has little fixed sequence left to encode. And a workflow with very small volume, run rarely, simply never earns back its setup cost, no matter how tedious it feels by hand.

Weighing these factors is a judgment call, not a formula — but it's a judgment call with real financial and time consequences, which is exactly what the final section of this chapter puts numbers to.
