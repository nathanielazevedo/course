With the structure and API covered, this section is a tour of the registry patterns you'll actually reach for in real C# applications — the specific, well-known keys Windows itself reads for startup, uninstall, and file associations, plus where an app's own settings should live.

### Running at startup

The most common startup mechanism for a simple app is a value under one of the `Run` keys — Windows checks these at every logon and launches whatever's listed:

```csharp
using RegistryKey run = Registry.CurrentUser.OpenSubKey(
    @"SOFTWARE\Microsoft\Windows\CurrentVersion\Run", writable: true)!;
run.SetValue("MyApp", $"\"{Environment.ProcessPath}\"");
```

`HKCU\...\Run` starts the app for the current user only, no elevation required. `HKLM\...\Run` starts it for every user on the machine, and requires administrator rights to write. There's also `RunOnce` (same location pattern, `RunOnce` instead of `Run`) for a value that Windows automatically deletes after running it once — useful for a post-install step that should fire exactly once, not on every future logon. For anything beyond "launch this executable" — delayed start, conditional triggers, retry policy — the Task Scheduler API (Chapter 11) is the more capable tool; the `Run` key is genuinely just "launch this at logon," nothing more.

### Registering an uninstaller

Programs that show up in "Apps & Features" / Control Panel's "Programs and Features" do so because they've registered a subkey under:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\{ProductGuid}
```

```csharp
using RegistryKey uninstall = Registry.LocalMachine.CreateSubKey(
    @"SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\{B3F1A1E2-...}");
uninstall.SetValue("DisplayName", "My App");
uninstall.SetValue("DisplayVersion", "1.2.0");
uninstall.SetValue("Publisher", "Contoso");
uninstall.SetValue("UninstallString", @"C:\Program Files\MyApp\uninstall.exe");
uninstall.SetValue("EstimatedSize", 45000, RegistryValueKind.DWord); // KB
```

This is registry data Windows itself reads, not just a convention — the values above are exactly what populates the name, version, publisher, and size columns of the Programs and Features list, and `UninstallString` is what actually runs when a user clicks Uninstall. In practice this is more commonly written by an installer (MSI/MSIX/WiX, Chapter 11) than by application code directly, but knowing the shape of it explains what an installer is really doing under the hood.

### File associations

Associating a file extension with your app touches `HKEY_CLASSES_ROOT` (or, per-user and without elevation, `HKCU\Software\Classes`, which merges into the same `HKCR` view from earlier in this chapter):

```csharp
using RegistryKey ext = Registry.CurrentUser.CreateSubKey(
    @"Software\Classes\.myext");
ext.SetValue("", "Contoso.MyApp.Document"); // the default value links ext -> ProgID

using RegistryKey progId = Registry.CurrentUser.CreateSubKey(
    @"Software\Classes\Contoso.MyApp.Document\shell\open\command");
progId.SetValue("", $"\"{Environment.ProcessPath}\" \"%1\"");
```

The **default value** of a key (the unnamed one, set with an empty-string name in `SetValue`) is doing real work here — it's the indirection that lets multiple extensions share one ProgID definition rather than duplicating the open command per extension.

### Where your own app settings should — and shouldn't — go

Given everything covered in this chapter, the practical guidance: put genuinely OS-integration-level data in the registry — install paths other tools need to discover, uninstall registration, file associations, startup entries, licensing/activation state that should survive a reinstall of just the app's files. Put ordinary application preferences — window size, last-opened file, feature toggles — in a config file (`appsettings.json`, or a file under `%APPDATA%`) instead, using `System.Configuration` or the `Microsoft.Extensions.Configuration` stack most modern .NET apps already use. The registry's transactional durability and access control are wasted on data nobody but your own app ever needs to read, and a JSON file is trivially easier to inspect, version, and back up.
